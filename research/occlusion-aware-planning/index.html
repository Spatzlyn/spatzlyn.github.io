Possible Hazards Lost Before Safety Checks: A case study in occlusion-aware motion planning

Yookyung Youn

Korea University

CodeReproduction guide

Abstract

An occlusion-aware planner must account for road users whose positions remain possible given the available observations. In a controlled replay, a rule for skipping repeated work suppressed a feasible hidden position. An independent finite trajectory reference verified feasibility, and admitting a single skipped computation restored the position. In a separate checker experiment, restoring omitted possibilities reduced the permitted set from 18 of 18 fixed candidate actions to 4 of 18. The experiments trace how a loss of coverage can affect downstream decisions.

One skipped computation

A short computation marked a search key as visited. When a later computation reached the same key with more work to do, the planner skipped it. Starting from an identical execution prefix and admitting that one computation restored the missing location. A separate finite trajectory reference established that the stationary position was feasible.

Did the omission change a decision?

In a separate upstream control, the checker permitted all 18 candidates under every method. The effect depended on where the candidate was checked. These comparisons measure permissions in a saved scenario. No vehicle actions were executed.

What the evidence covers

Reproducing the omission

Synthetic depth sequences provide a second way to examine the omitted position. The artifact keeps this sensor experiment separate from the downstream checker comparison.

Scope of the repair

Restoring a feasible position identifies the cause in this controlled case. It leaves open whether other reductions preserve all relevant hidden states across continuous trajectories.
